# Phase 2 · 检查点 9b 报告：Google Drive 云存档

日期：2026-10-31 · 分支 `phase-2/checkpoint-9b`。

## 1. 结论
**实现完成，待真实 Google 和双机验证。** 手动备份、恢复、冲突处理、启动前检查、关闭后备份都已实现，用两个独立资料库共用一个假 Drive 跑通。**没有连接过真实 Google**：需要用户先建 Google Cloud 项目（第 7 节），这一步规范不允许代做。

这是 Atlas 的云存档，不是 DLsite 官方功能，也不保证不同游戏版本的存档兼容。

## 2. 授权和存储方案
- **客户端**：桌面应用，用户自己的 Google Cloud 项目。系统浏览器打开 Google 官方页面，回环地址 + 随机端口接收结果，PKCE S256，`state` 一次性。官方文档没有说回环地址能否带路径，所以每次单独开一个端口，只收根路径，收到后立即关闭，5 分钟超时。
- **权限**：只有 `drive.file`。Atlas 只能看到自己创建的文件。
- **存储**：用户能在 Drive 里看到的文件夹“Library Atlas 云存档”。靠 `appProperties` 标记识别，不靠名字：用户自己同名的文件夹不会被认领。
- **令牌**：刷新令牌和客户端密钥在 Windows 凭据管理器，访问令牌只在内存。不进数据库、日志、地址、页面。
- **断开**：只清这台电脑的授权。不吊销（吊销会让另一台电脑也失效），不删云端和本地。

## 3. 快照
一份快照 = 数据文件 + 提交文件。数据上传后比对 MD5 和大小，通过才上传提交文件；**没有提交文件的快照不算存在**。

- 不可变，每次新增，不覆盖。
- 记录父快照、设备 ID、设备名、时间（仅显示）、每个文件的相对路径/大小/SHA-256。不含绝对路径、作品名。
- 打包前后各算一次摘要，不一致就拒绝（游戏可能还在写）。
- 重试安全：先查云端已有的，响应丢失或重启后不会重复，也不会误报成功。
- 分块上传走官方可恢复协议，断线后问清进度再继续。

## 4. 多设备
只看历史和内容，**不比较时间**。

| 情况 | 结果 |
| --- | --- |
| 内容和云端最新一致 | 已同步 |
| 只有本机变了 | 本机有新进度 |
| 只有云端变了 | 云端有更新 |
| 本机没有存档 | 云端有更新（缺失不是删除指令） |
| 两边都变了，或没有共同基线 | 冲突 |
| 云端有多个分支 | 冲突 |
| 查询失败 | 查询失败，不当成云端为空 |

上传时父快照是本机的基线，不是刚看到的云端最新，所以并发会形成分支，两边数据都保留。

选择一份后，写一个以所有分支为父的新提交，两台电脑上都算解决。没选中的分支留在历史里。

## 5. 恢复
下载到暂存 → 比对 MD5 和大小 → 成员清单必须和快照列表完全一致 → 逐个校验 SHA-256 → 先做本地备份（失败就停）→ 逐文件替换 → 记录新基线。

- 只写规则列出的位置。路径穿越、未知 schema、存档位置配置不一致都拒绝。
- 快照里没有的文件不删。
- 主程序在运行，或用户没确认已关闭，拒绝。
- 文件和数据库不是一个事务：恢复期间打标记，崩溃后显示“上次恢复没有完成”，可重来。

## 6. 自动化（默认都关）
- **启动前检查**：有更新或冲突时先问，可以选“仍然启动”。查不到时提示并照常启动。**不会自动恢复**，这比规范允许的更保守：还没有真实使用证据之前，不让程序自动覆盖存档。
- **关闭后备份**：游戏结束后备份，结束判断见[游玩记录报告](PLAY_TRACKING_REPORT.md)，启动器拉起的游戏也能跟踪。需要管理员权限运行的游戏跟不到，仍需手动。它只会新增快照，判断错了最多多一份。

## 7. 真实使用前的设置（用户）
1. 打开 console.cloud.google.com，新建项目。
2. 启用 Google Drive API。
3. 配置 OAuth 同意屏幕，添加自己的账号为测试用户。**“测试”状态下授权 7 天过期**，不想重复连接可以发布应用。
4. 创建 OAuth 客户端，类型选“桌面应用”。
5. 在 Atlas 设置 → 云存档填客户端 ID（Google 给了密钥也填上），点连接。

两台电脑要用同一个客户端 ID。不要把 ID 或密钥发到聊天里。

## 9. 已知限制
- **不自动恢复**，也**没有云端清理**：快照只增不删，长期会占空间，要在 Drive 里手动删。这是首批的保守选择，规范要求不能误删唯一恢复点。
- 不加密，文件在你的 Drive 里是普通 ZIP。Drive 的校验能发现损坏，不防篡改。
- 单作品存档上限 8 GB、5 万个文件。
- 换了存档位置配置后，旧快照不能恢复（第 5 节）。
- 存档位置的查找见 [查找存档位置报告](SAVE_DISCOVERY_REPORT.md)。
- 恢复不删除快照里没有的文件，恢复后可能显示“本机有新进度”。
- 只读默认副本。设备名是这台电脑的计算机名，会写进你自己的 Drive。
- 启动前检查只在从详情页启动时生效，右键菜单的“开始游戏”还没有接入。

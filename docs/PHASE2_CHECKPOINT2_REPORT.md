## 1. 结论

## 2. 实际机制
- DLsite 没有找到面向第三方的公开授权，这不是 OAuth。使用的是普通网页登录加 DLsite Play 的非公开接口，第三方代码（dlsite-async，MIT，只读参考，未复制）是接口线索的来源。接口可能随时变化。
- **用户决定 D1（2026-10-31）**：不能有在网页上登录的感觉。用户在 Atlas 面板输入账号密码，隐藏的 WebView2 提交；用户接受密码经过 Atlas 和代为填表。保留备用网页登录。
- 后端直接提交不可行：登录页对非浏览器请求返回 Cloudflare 质询。隐藏的 WebView2 是真实浏览器引擎，没有修改任何指纹。
- 会话保存在 Windows 凭据管理器（`LibraryAtlas/real/…`，超过单条 2560 字节时分片）。数据库只存凭据引用、账号哈希、打码账号和状态。前端只能看到状态和打码账号。

## 4. 策略
- **取消与竞态**：一次一个尝试；取消、替换后的结果丢弃；校验中途取消或退出登录，结果不写入。
- **区分失败**：平台明确拒绝 → 需重新登录；网络、限流、Cloudflare → 暂时无法验证，保留会话；凭据存储读取失败单独说明，不怪账号；会话损坏 → 需重新登录。
- **保存**：先校验，再写凭据，最后写数据库。分片全部写完才写清单，失败时旧会话不受影响。写入失败不显示已连接，也不改存明文。
- **网页登录的限制**：Atlas 看不到账号，无法做换号确认，也没有打码账号。

## 5. 请求边界评估（检查点 1 遗留）
登录接口现在接收密码，因此重新评估。

| 攻击 | 防护 | 结论 |
| --- | --- | --- |
| 网页跨站发起登录或退出 | Origin + Sec-Fetch-Site + CSRF，无 CORS | 已防，有测试 |
| 网页读取账号状态或文件夹 | 同上；带 Origin 的跨站读取被拒 | 已防，有测试 |
| DNS rebinding | Host 校验 | 已防，有测试 |
| 从接口取走会话或密码 | 没有任何接口返回它们 | 不存在该路径 |
| 同用户恶意程序 | 可直接读凭据和数据库，bootstrap 也挡不住 | 不在防护范围 |
| 同机其他 Windows 用户的进程访问回环端口 | 可读普通作品、可触发退出登录，但拿不到会话 | **未防**，bootstrap 可缓解 |

**结论：本点不补 bootstrap。** 它主要防范最后一项，而这是单人电脑上的本地应用；补它需要启动器发放令牌，会改变打开方式。建议在 Phase 5 发布前重新评估。

## 7. 过程中发现并修复
- 登录在后台结束时，来源徽标不更新（回归和用户截图都发现）。
- 验证页上等待时限每轮重置，可能永不超时；现在只计一次。
- 第三方 HTTP 库把请求地址写入日志；将来的下载地址可能带签名，已关闭其 INFO 日志。
- 换号确认按钮等待逻辑依赖固定时间，改为等待明确结果。
- 登录失败回到表单时账号被清空（CI 较慢的机器发现，本机太快看不到中间状态）。账号状态提到面板一层，假平台加延迟后可稳定复现。
- 一次未复现的测试超时：同时运行真实服务、单项时限压到 30 秒时出现 1 次，之后连续多轮未再出现，原因未确认。

## 8. 已知限制
- 接口非公开，可能随时变化；变化时面板提示改用网页登录，同步类功能会受影响。
- 登录页判断（成功、被拒、需验证）只有成功路径经过真实验证。
- 已连接的现有会话在下次登录前显示“DLsite 账号”，因为打码账号是后来加的。
- Python 无法保证密码立即从内存抹除。
- 记住密码后，同一 Windows 用户下的程序可以从凭据管理器读取它。
- 会话过期时不会自动用保存的密码重新登录，需要点一下；是否自动由用户后续决定。
- 自动填表可能被平台视为自动化操作（利用規約第 17 条第 11 号）；用户已知情并接受。
- 退出登录只清除 Atlas 保存的登录，不代表平台端所有设备退出。
- 文件夹选择窗口用 tkinter，外观是系统标准样式。
- 本机证据截图中含临时目录路径（合成测试），不入库。

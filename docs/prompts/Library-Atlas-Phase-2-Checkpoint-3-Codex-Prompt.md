你担任本项目的高级前后端工程师与作品库集成负责人。

## 四、同步任务与恢复

### 4.1 用户触发与状态

- 用户在真实模式明确点击同步；登录成功、打开页面或服务启动不能默认触发整库请求。
- 任务由后端统一管理，前端只展示真实进度，不靠计时器伪造完成。
- 任务关联模式、来源、账号/库身份和会话生命周期，状态跨页面一致。
- 至少表达排队/准备、读取、入库、完成、部分失败、失败、取消，以及需要重新认证。
- 平台总量未知时显示已处理页/件数和不定进度，不能编造百分比。
- 最近成功同步时间只在满足本次完整成功条件后更新；本次尝试时间与成功时间分开。
- 同一库已有活动任务时复用/拒绝重复任务，不并发开启多个全库同步。

### 4.2 分页与一致性

- 按实际机制处理页码、游标、终止条件和重复页，设置合理超时、请求/页数保护，防止无限循环。
- 对重复条目、页面重叠、稳定排序变化和重复响应正确去重。
- 访问失败、空响应、结构变化、缺必要字段与正常空库必须区别，不能全部作为“没有作品”。
- 上游未提供一致快照时说明同步期间库变化的影响，采用可解释的稳定身份去重与重跑策略，不声称强一致全库快照。
- 有可靠增量机制才使用增量同步；否则采用受控完整读取与幂等更新，不以购买日期随意替代增量游标。

### 4.3 入库与中断恢复

- 事务边界明确，避免全库长事务占用数据库，也避免作品半写入。
- 采用按批/页提交或其他既定策略，记录任务检查点；中断后可安全重跑，只有可靠游标时才承诺从精确位置续跑。
- 部分成功是否可展示及何时更新统计有明确规则；前端不能把部分结果标成全库完成。
- 取消在合理边界生效，保留一致的已提交数据，不能取消后继续把任务改为成功。
- 服务重启后，遗留运行中任务转成可恢复/需重试的准确状态，不永久卡住、不无声自动重放所有请求。
- 网络/限流采用有限退避和重试，平台要求重新认证时停止并提示用户；普通网络失败不直接清除会话。
- 结构变化或数据契约不满足时停止该类解析并报告，不靠默认值把损坏响应写满数据库。

### 4.4 会话失效、断开与换号

- 每批写入前确认任务仍归属当前有效库/账号，不因旧响应污染新会话。
- 用户断开或切换账号时取消/停用原任务，迟到响应不得继续写入另一账号的库。
- 不将会话过期理解为全库为空，不删除旧作品、评分或下载状态。
- 无法可靠识别账号的登录路径，遵循已确认限制；必要时提出最小、清楚的账号归属确认，不暗中合并两个账号。

## 五、作品身份、字段与更新边界

### 5.1 身份模型

- 延续本地稳定作品身份，以及来源、来源作品 ID、账号/库归属之间的既定关系。
- 来源 ID 是不透明身份，不能未经验证按数字提取、去前缀、改大小写或截断后合并。
- Steam 与 DLsite 同名/同 ID 不合并；不同语言、版本、套装与文件关系按实际来源机制表达。
- 一个作品可以有多个文件/版本/分卷引用，不把分卷当成多件作品，不把全部文件覆盖成一个 URL。
- 保留现有前端深链接与个人编辑关联；必要迁移先备份、验证恢复，不删库重建。

### 5.2 元数据映射

按实际可得信息映射：标题、作者/社团、来源链接、内容类型、标签、简介、封面/背景引用、适用的发行/获取时间、文件/版本描述等。

要求：

- 列出来源字段 → 领域字段 → 空值/未知处理规则，不把平台原始 JSON 原样交给页面。
- 明确“未提供”“此次未读取”“明确为空”之间的更新语义；部分响应缺字段不能清空本地完整数据。
- 平台提供 HTML 简介时按既定安全规则转成可展示内容，不将未知 HTML/脚本直接注入页面。
- 无游玩记录不等于未开始；购买时间不等于最近游玩；商品时长不等于用户播放时长。
- 大小、时间、时长、日期的单位与时区明确，未知值不能变成 0 或当前日期。
- 非游戏不伪造游戏安装、成就、可执行文件或游玩时间。
- 本点仅保存必要且稳定的文件/版本元数据，不主动取得或长期保存敏感临时下载 URL。文件列表若需额外广泛请求，先说明必要性，能留到下载检查点的就不做。

### 5.3 个人记录必须保留

来源更新只修改来源拥有的字段，不覆盖：

- 用户评分、备注、收藏。
- 自建分类、手动修正及其既定优先级。
- 本地隐藏/私人标记与已确认可见性。
- 本地路径、用户设置与已有任务/文件状态。

作品暂不可访问、来源返回缺项或一次同步失败时，不直接删除库存、清空个人记录或标成用户已退款。下架/不可访问只在有证据时更新独立来源状态。

## 六、多类型分类与隐私

### 6.1 内容类型

保留一级类型：游戏、漫画/图像、音声、视频、其他；允许未知/待分类语义，必要子类型按现有模型表达。

- 优先依据来源明确类型；来源值与映射版本/依据可追踪，不根据封面、标题关键词或下载扩展名强行猜测。
- 标签/题材、自建分类与一级内容类型分开，RPG 等不能代替“游戏”这个类型维度。
- 未识别类型归其他/待分类并保留必要来源值，不能丢弃作品。
- 多标签计数说明是否重复计数，互斥类型统计与标签分布不混用。
- 作品类型与来源没有一一对应关系，不将 DLsite 默认当游戏或默认当音声。

### 6.2 可见性先于展示与聚合

- 读取并执行仓库统一服务端可见性策略；未知隐私状态按适用规范先隔离，不能为了让同步数量好看默认设为公开。
- 来源购买/访问状态与 Atlas 本地私人标记分离。来源若没有隐私字段，不能把“字段不存在”解释为“已确认公开”。
- 新作品如何进入普通作品库必须有明确、已确认的本地可见性规则；必要时提供最小的导入可见性选择/待确认提示，不擅自开发完整私人库。
- 不得把未知或私人条目先传到普通页面再用 CSS 隐藏，图片接口也应用相同规则。
- 隐私过滤先于列表、搜索、详情、修改、普通计数、分类、统计和推荐。
- 同步任务的账号级导入摘要与普通可见作品数是不同口径，不能以公开聚合泄露隔离作品信息；仅在合适的用户主动同步状态界面显示必要、受约束摘要，不输出私人标题。
- 导入数量与可见数量不一致时用安全说明解释“已导入范围与普通可见范围不同”，不能伪称丢数据或暗中放开隐私。
- 测试和截图使用合成数据；私人哨兵只断言不存在，不转储内容。真实资料、原始响应、凭据和私人路径不进日志、Git、截图或 trace。

## 七、封面与背景缓存

- 仅按已核对的资源获取方式及允许条件缓存展示所需资源，不以同步为理由下载作品正文或全部媒体。
- 区分必要元数据同步与可延后图片任务；图片失败不让整库同步失败或抹掉已有图片。
- 保持有限并发、大小/超时限制与失败回退，避免 1500/5000 件作品同时发起图片请求。
- Library 继续可见区域附近的懒加载与虚拟化，不请求全部大图。
- 缓存键关联来源和稳定资源身份，不使用任意标题拼文件路径；缓存写入限定在应用缓存目录。
- 受登录保护的资源由服务端在受控边界获取，不能把 Cookie 或敏感签名 URL传给普通展示组件；如需图片代理，限制上游主机、重定向与响应大小，不能变成任意 URL 抓取接口。
- 私人/未知条目的图片访问遵循同一可见性策略，不可通过猜测图片路径绕过。
- 图片缓存丢失或过期不删除收藏，旧缓存更新按明确策略处理，不清理用户作品目录。
- 保留本地字体、精致占位和失效回退，不用拉伸低分辨率图掩盖缺图。

## 八、前端真实同步与三页接通

### 8.1 来源面板与同步操作

- 沿用 Atlas 简洁视觉，真实模式提供“同步作品库”及进度/结果，不增加密集的技术参数面板。
- 未连接/待重新认证时给出对应入口；同步只调用现有会话服务，不另开长期认证流程。
- 展示已处理数量、范围、当前阶段与清楚的取消/重试结果；未知总量不显示虚假百分比。
- 成功、部分失败、取消、失败清楚区分。失败时保留已存在收藏，不显示“0 件全部同步完成”。
- 清楚说明本次未开始下载，下载操作仍标注待后续接入。
- 相同任务在不同页面状态一致，刷新/服务重启后能查看准确结果。

### 8.2 Library

- 真实作品进入统一服务端列表与查询缓存，页面不能直接 import 原始同步响应。
- 来源、内容类型、分类、名称搜索、排序与已有适用筛选真正作用于数据。
- 分页/窗口加载与虚拟化协同，不将整个真实库一次性传到前端再渲染。
- 网格/列表的封面、长标题、缺图和非游戏卡片保持既有设计。
- 搜索、筛选后的可见计数和后端范围一致；同步中/完成后缓存合理更新，避免每写一条就全页面闪烁。

### 8.3 Detail

- 显示正确的真实标题、来源、作者/社团、简介、类型/标签与适用字段。
- 不展示虚构成就、游玩/播放记录或下载成功状态。
- 评分、备注、收藏等编辑继续保存到个人记录，并在后续同步后保留。
- 原详情链接、刷新、前进后退和返回 Library 的条件/滚动恢复正常。
- 特殊格式、不可用版本或字段缺失准确表达，不承诺所有作品均可直接启动。

### 8.4 Dashboard

- 作品总数、来源/内容类型统计使用同一过滤口径，不能把全部 DLsite 作品称为游戏。
- 游戏专属统计只使用确有记录的游戏，未知时间不加入累计时长或自动列为未开始。
- 最近获取与最近使用分开，没有真实使用记录时给精致空状态，不用 Demo 填满。
- 推荐与精选排除私人/未知条目，规则可解释，不凭购买信息猜测用户播放记录。
- Demo、真实模式、测试夹具及账号切换的查询缓存隔离，旧响应不得覆盖当前页面。

## 九、测试计划

### 9.1 适配器、映射与同步服务

使用隔离服务、临时数据库和合成夹具，覆盖：

- 正常分页、空库、重复页/记录、游标缺失/循环、结构变化和未知类型。
- 缺字段、明确空值、HTML/文本简介、日文与中英混排、多个文件/版本。
- 网络失败、限流、有限重试、认证失效与平台暂不可用的区分。
- 重复同步与中断重跑幂等，不产生重复作品或丢失个人编辑。
- 元数据刷新、来源缺项、不可访问不清空备注/评分/隐私。
- 单库重复任务、取消、重启恢复、断开/换号后的迟到响应隔离。
- 事务失败不留下半条记录；部分成功统计与成功时间正确。
- 可见性、图片接口、普通计数、搜索、详情/修改和推荐统一过滤。
- 图片获取失败、非允许目标、超大响应与缓存回退。

不要把所有平台响应和仓储都 mock 掉后宣布幂等与持久化已验证；至少通过真实本地数据库/API验证这些关键行为。

### 9.2 前后端端到端与视觉

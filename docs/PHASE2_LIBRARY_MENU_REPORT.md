# Phase 2 · 作品右键菜单、卸载与收藏夹 报告

日期：2026-10-31 · 分支 `phase-2/library-menu`。用户直接提出，不属于编号检查点。

## 1. 结论
**实现完成，真实作品待人工验证。** 真实卸载和真实快捷方式只在合成文件夹上试过。

## 2. 做了什么
- **右键菜单**：作品库卡片和列表行。有本地文件的游戏是“开始游戏”，有本地文件的其他作品是“打开”，没有的是“安装”。下面是添加至收藏夹、添加至、管理、属性。键盘可操作。演示模式不显示。
- **管理**：只有添加桌面快捷方式、浏览本地文件、卸载。
- **卸载**：详情页和菜单都有。
- **收藏夹**：侧边栏入口、列表页、新建、重命名、删除。“添加至”可以放进多个收藏，点开可以筛选作品库。
- **启动**：匹配上文件夹就显示“启动”，不再显示“下载并解压”“重新下载”。有更新或下载出错时仍会提示。
- **选择程序**：没定主程序时点启动，会列出文件夹里的程序让用户选，选好记住并启动。
- **已安装**：有本地文件就算已安装。之前只看下载记录，扫描关联的作品不算。

## 3. 卸载的保护
移到回收站，可以恢复。收藏、评分、记录都保留。

先显示完整路径、文件数和大小，用户确认后才执行，请求必须带上用户看到的路径，不一致就拒绝。

拒绝的情况：
| 情况 | 原因 |
| --- | --- |
| 系统文件夹、整个盘、Atlas 数据目录 | 不是作品 |
| 用户为 Atlas 选择的文件夹，或包含它们 | 里面有别的东西 |
| 作品库本身，以及类型、制作方这两层 | 里面有别的作品 |
| 和另一个关联文件夹重叠 | 会删到别的作品 |
| 符号链接或目录联接 | 不是作品本身的文件夹 |
| 主程序正在运行 | 写打开失败判定，不完整，回收站失败时同样什么都不做 |
| 这部作品正在更新或等待确认 | 等更新结束 |

回收站失败时不删记录。文件夹太大放不进回收站时，Windows 会弹窗询问，这个窗口可能在浏览器后面。

**放不下的文件夹，如果用户在 Windows 弹窗里同意，会被永久删除。** 这一步由 Windows 决定，Atlas 不控制。

手动关联的文件夹如果本身混放了别的内容，规则识别不出来，所以确认框一定显示路径和大小。

## 4. 收藏夹
- 星标“收藏”和“添加至”是两回事：前者一部作品一个开关，后者是用户自己命名的多个分组。
- 隐藏、私人、隔离的作品不出现，也不计入数量。
- 删除收藏不影响作品。

## 5. 用户后续要求（2026-10-31）
- **记住路径**：关联保存在数据库，重启不丢，有测试。详情页现在直接显示路径。作品更新后文件夹改名（如 `ver121` 变 `ver200`），下次扫描会关联新文件夹并设为默认，旧记录保留并标记为不存在。
- **设置里手动关联**：“没有匹配”和“需要确认”的每一行都有“手动选择作品”，默认按制作方搜索，点一下就关联，之后扫描不会改动。
- **滚轮翻页**：见阅读器。

## 6. 改掉的误导

- “加入收藏”日期其实是加入作品库的时间，已改名。

## 8. 已知限制
- 回收站不释放磁盘空间，要清空回收站才释放。
- 卸载只处理默认副本。另一个盘的副本要先切换默认。
- 路径过长的文件夹可能进不了回收站，会提示失败，不会删除。
- “开始游戏”从菜单启动时，定了主程序的直接启动；没定的跳到详情页让用户选。
- 列表数据有缓存，卸载后立刻刷新，从外部删除文件夹最多 30 秒后才在详情页显示。
- 演示模式没有菜单和收藏夹。

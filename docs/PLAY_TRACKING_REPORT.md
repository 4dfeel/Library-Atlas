# Phase 2 · 游玩记录 报告

日期：2026-10-31 · 分支 `phase-2/save-discovery`。用户直接提出，不属于编号检查点。

## 1. 结论
**实现完成，真实游戏待人工验证。** 自动测试用真实进程和真实 Job 对象验证（一个合成的启动器和它的子进程，一个 Windows `ping` 副本），没有启动过真实游戏。

## 2. 记录什么
DLsite 不提供游玩数据，由 Atlas 记录：每次的开始、结束、时长、来源。详情页显示累计和最近游玩，“游玩记录”页显示累计、最近两周、每月时长和当月排行、最近玩过的游戏。

## 3. 和 Steam 的统一方式
- 作品上的 `playtime_minutes`、`last_used_at`，就是 Steam 的 `playtime_forever`、`rtime_last_played` 的位置，首页和作品库已经在读这两个字段。DLsite 的值由 Atlas 汇总写入。
- `play_sessions.source` 标明来源。现在只有 `atlas`。
- 接入 Steam 时要定的规则：Steam 只给累计和两周，不给每次记录，所以累计以平台数字为准，从 Atlas 启动的 Steam 游戏仍然产生 session 用于月度统计。两边的数字不相加。
- 同步不会覆盖这些字段：DLsite 不报告时保留 Atlas 的值，有测试。

## 4. 怎么判断结束
Windows Job 对象：跟踪进程和它启动的所有子进程，**启动器拉起游戏后退出不算结束，最后一个进程退出才算**。Job 有名字，Atlas 重启后能重新找到。

这也取代了之前存档查找和关闭后备份用的轮询判断，它们现在等这个结束事件。

## 5. 规则
| 情况 | 处理 |
| --- | --- |
| 不足 10 秒 | 记录但不计入（多半是启动失败） |
| 电脑睡眠 | 不计入，两次检查的间隔有上限 |
| 重复启动同一游戏 | 不重复计时 |
| Atlas 重启时游戏还在运行 | 接着记 |
| 游戏在 Atlas 没运行时结束 | 记到最后一次记录的时间，标“估算” |
| 跨月 | 按本地时间拆到两个月 |
| 隐藏、私人、隔离的作品 | 不出现，也不计入总数 |

## 7. 已知限制
- 只统计从 Atlas 启动的游戏。以前玩的时间平台没有提供，补不回来。
- 开着不玩也算，和 Steam 一样。
- 要求管理员权限（UAC）运行的游戏会脱离 Job，可能很快被判定为结束，时长偏短甚至不计入。把任务交给已运行程序的启动器同理。
- 游戏留下后台进程时，会一直算运行中，时长偏长。
- 没有手动修改时长的功能。

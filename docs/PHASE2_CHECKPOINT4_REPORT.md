## 2. 前序条件与下载机制
- 复用检查点 2 的会话（Windows 凭据管理器）和检查点 3 的作品库。不新建登录，不读浏览器 Cookie。
- **机制的证据**（2026-10-31 阅读）：[dlsite-manager](https://github.com/vuhe/dlsite-manager)（MIT，提交 `36bed5b`）的 `dm-api`、`dm-download` 源码。证据层级是**代码层**，接口非公开，可能随时变化。
  1. `GET play.dlsite.com/api/v3/download?workno=…` 返回跳转。
  2. 跳转目标决定交付方式：`/home/download…` 单个文件；`/home/download/split…` 或 `/home/split…` 分卷页面，页面里列出带 `/number/N/` 的链接；`/home/download/serial…` 或 `/home/serial…` 需要序列号。
  3. 文件地址继续跳转后返回文件；文件名在 `Content-Disposition` 或地址的 `/file/<名称>` 段。
- `dlsite-async` 只能下载网页优化版，不是原版文件，所以没有采用。
- **待真实核实**：保存的会话能否访问 `www.dlsite.com` 的下载地址；最终文件在哪个主机；是否支持 Range、是否有 ETag；`content_size` 的单位。

## 4. 目录、临时文件与提交
- **位置**：完成的文件在 `<作品文件夹>/<作品编号>/<文件名>`；下载中的文件在 `<下载缓存>/<任务号>.part`。这两个文件夹是设置页已有的。文件夹在任务创建时固定，之后改设置不会移动已有任务。
- **文件名**：只取最后一段，清理非法字符、Windows 保留名和结尾的点与空格，限制长度并保留扩展名。没有名字时用作品编号。不用作品标题作身份。
- **越界**：提交前解析真实路径，必须正好在所选文件夹下一层。联接点（junction）指向外面会被拒绝。请求不能指定路径。
- **不覆盖**：同名文件永远保留，新文件改名为 `名称 (2).zip`。同名同大小不认为是同一文件。
- **提交**：传输结束 → 校验 → 记下最终文件名和哈希 → 移动 → 标记完成。跨盘时先复制到目标旁边再改名。
- **清理**：只删除本任务自己的 `.part` 和临时文件，不扫描目录。取消时删除半成品；网络失败和暂停时保留，用于续传；空间不足时删除。
- 所选文件夹不存在时报告，不重建（可能是硬盘没接）。缓存的默认位置在数据目录，需要时才创建。

## 5. 队列、幂等与恢复
| 项目 | 规则 |
| --- | --- |
| 状态 | queued、resolving、downloading、verifying、paused、done、failed、cancelled、reauth_required、interrupted，全部存数据库，由后端驱动 |
| 并发 | 同时最多 2 个，其余排队 |
| 重复请求 | 同一文件的进行中任务由数据库唯一约束保证只有一个；重复点击返回同一任务 |
| 已完成再请求 | 文件还在就返回原任务；选“重新下载”才新建，不覆盖 |
| 自动重试 | 网络、限流、5xx 最多 3 次，尊重 Retry-After。地址被拒绝时换一次新地址 |
| 取消 | 每次写入前检查。取消与完成在提交点加锁：先到的算数，不会显示取消却写出文件 |
| 迟到的工作线程 | 每次写入都带尝试号，旧尝试写不进去 |
| 重启 | 活动任务标记为中断，不自动联网，由用户继续 |
| 崩溃窗口 | 校验中崩溃时看文件：最终文件存在且哈希一致算完成，否则算中断 |
| 文件被移走 | 任务显示“文件已经不在原位置”，作品本机状态变回未知，可以重新下载 |
| 退出或换号 | 传输中校验会话代次，变化即停止，不用新会话继续。任务绑定账号指纹，其他账号不能继续 |
| 可见性 | 隐藏、私人、待确认作品：不能建任务，不进任务列表和计数，已有任务也不能操作 |

## 6. 暂停与续传
**只在同时满足这些条件时续传**：有强校验器（非弱 ETag 或 Last-Modified）、知道总大小、部分文件还在。请求带 `Range` 和 `If-Range`。

| 服务器的回答 | 处理 |
| --- | --- |
| 206，偏移和校验器都一致 | 接着写 |
| 200（忽略 Range 或文件变了） | 清空，从头写，绝不追加 |
| 206 但偏移不符、校验器或总大小变了 | 丢弃，从头下载 |
| 416 | 丢弃，从头下载 |
| 没有校验器或大小未知 | 不续传；界面显示“重新下载”而不是“继续” |

暂停按钮已提供，**续传只在本地服务上验证过**，真实 DLsite 是否支持待核实。不支持时会自动走“从头下载”，不会损坏文件。

## 7. 完整性依据
| 依据 | 说明 |
| --- | --- |
| 响应类型 | `text/html`、`application/json`、`text/plain` 直接拒绝；第一块内容像网页也拒绝，即使它标注为压缩包。这样登录页不会被存成文件 |
| 长度 | 有 `Content-Length` 或 `Content-Range` 时必须完全一致（`integrity=length`） |
| 无长度 | 只能确认传输正常结束（`integrity=stream_end`），界面写明“完整性保障有限” |
| 本地 SHA-256 | Atlas 自己算的，用于崩溃恢复和以后比对。**不是官方校验**，平台没有公布哈希 |
| 空文件 | 视为失败 |

没有用解压来验证文件。

## 8. 安全
- 前端只提交作品编号和分卷号，收不到 Cookie 和下载地址。下载地址不写入数据库、日志、错误信息和 API 响应。
- 每一跳先判断再发送：只允许 `https` 且主机为 `dlsite.com` 或其子域、默认端口。跳到其他主机时什么也不发送并报错，日志只记主机名。
- Cookie 按域匹配，只会发给平台。
- 跳到登录页单独报告（`login_required`），不会误判为整个会话失效。Cloudflare 质询报告后停止，不重试、不绕过。
- 下载、取消、打开文件夹等都走现有 CSRF 和回环边界。查询下载方案也用 POST，因为它会动用会话。
- httpx 和 httpcore 的日志在适配器里被屏蔽，因为它们会记录完整地址。

- **检查点 3 遗留的真实 Bug**：顶部收起时如果搜索结果变短，列表滚不动，顶部再也展开不了。现在切换筛选会展开，“回到顶部”也立即展开（`c2b4ae1`，回归测试已确认没有修复时失败）。
- 同样原因导致 `real-mode` 大数据用例卡住；排序测试依赖服务里的作品数量。均已修复（`73a88d6`）。
- 暂停时没有记录最新进度，界面误判不能续传：已修复。
- 详情页同时出现灰色占位和可用的“打开文件夹”：已去掉占位。

## 10. 已知限制
- 真实机制只在一个单文件作品上验证过。其他情况可能的失败方式都有明确报错：`login_required`（会话不覆盖 www）、`unexpected_host`（文件在 dlsite.com 以外的主机）、`response_changed`（跳转路径不认识）、`challenged`。发生时报告错误码即可定位。
- 需要序列号的作品不支持。
- 第三方代码显示，部分可直接下载的作品也有序列号页面。Atlas 没有读取它，这类作品的序列号要到 DLsite 网站上查看。
- 分卷的单个大小未知，只显示平台给的总大小（来自 `content_size`，单位未核实）。
- 没有速度和剩余时间：还没有可靠样本，不编造。
- 服务器不给长度时，完整性保障有限。
- 崩溃发生在“标记完成”和“删除半成品”之间时，缓存里会留下一个 `.part`。
- 任务列表最多显示最近 200 条。
- 同时 2 个的并发上限没有在 DLsite 上验证过是否合适。

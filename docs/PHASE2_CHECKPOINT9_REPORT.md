# Phase 2 · 检查点 9 报告：存档保护优先的游戏更新

日期：2026-10-31 · 分支 `phase-2/checkpoint-9`。

## 1. 结论
**实现完成，真实更新待人工验证。** 完整的替换、清理、恢复都用合成目录和真实文件操作测试过。**夜间没有更新、替换或删除任何真实游戏和存档。**

## 2. 流程
1. **存档**：按用户列出的位置备份。每个文件读回比对，再恢复到隔离目录比对一次。失败就停止，后面的步骤都不会开始。
2. **下载**：复用 C4 队列。重试时复用已下载好的文件。
3. **解压**：复用 C5 的检查，放在旧目录旁边的 `.atlas-update-<任务号>`，同一个卷。
4. **判断是否完整**：新文件里没有原来的主程序就停止。这是用来区分完整本体和补丁、语言包的规则，**是启发式判断**。
5. **替换**：改名把旧目录移开，再把新目录改名就位。
6. **迁入存档**：只迁移列出的位置，逐个校验。用户的存档优先于新版本里的同名文件。旧目录的其他文件不复制回来。
7. **等待确认**：只有玩一下才知道新版本能不能读旧存档。旧目录保留，并列出它独有的文件数量和样例，然后由用户选择“清理旧版本”或“恢复旧版本”。
8. **清理**：只删除本任务创建、名字和位置都对得上的旧目录。备份不受影响。

## 3. 存档规则
| 情况 | 处理 |
| --- | --- |
| 没有配置 | **拒绝开始**。未知不等于没有存档 |
| 用户确认没有存档 | 可以开始 |
| 游戏目录内 | 备份并迁入新版本 |
| 目录外 | 备份，原位不动 |
| 列出但还不存在 | 记录为无，继续 |
| 路径越界、系统目录 | 拒绝保存 |

Atlas 不猜存档位置，也没有引擎识别。

## 4. 游戏是否在运行
无法写打开主程序时认为在运行，拒绝更新，不结束进程。这个检测不完整，所以还要求用户确认已关闭。

## 5. 失败与崩溃
| 时机 | 结果 |
| --- | --- |
| 备份、下载、解压失败，或取消 | 旧版本和存档原样不动 |
| 替换失败、存档校验失败 | 自动恢复旧版本 |
| 崩溃在替换中 | 重启时看磁盘：旧目录移回，新目录删除，标记中断 |
| 崩溃在等待确认时 | 继续等待 |
| 恢复旧版本 | 先备份新版本里的存档 |

替换后不能取消，只能选新版本或旧版本。

## 6. 备份
每部作品保留最近 5 份，只按数量清理，不随旧本体删除。恢复前先备份当前存档，逐个校验，只写规则列出的位置。位置在数据目录 `save-backups`。

## 8. 已知限制
- 区分补丁只看主程序是否存在，一个包含主程序的补丁会被当成完整本体。旧目录保留到确认，可以恢复。
- 新版本主程序改了名或路径会被拒绝，需要先改关联。
- 旧存档能否被新版本读取，Atlas 不知道，所以才要用户确认。
- 目录外的存档不会迁移；恢复备份时写回原位。
- 没有存档位置的自动识别。
- 取消下载阶段时，已下载的部分由下载队列处理。

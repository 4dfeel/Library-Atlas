# Phase 2 · 查找存档位置 报告

日期：2026-10-31 · 分支 `phase-2/save-discovery`。用户直接提出，不属于编号检查点。

## 1. 结论
**实现完成，真实游戏待人工验证。** 没有启动过任何真实游戏，也没有改过真实存档或真实注册表。测试只用合成目录和文件版注册表。真实机器上只做了只读统计，只输出数量。

**不保证能找到每个游戏的存档**，这件事本身做不到保证。所以 Atlas 只提建议，用户勾选确认后才算数。没有确认的位置不会被备份或上传。

## 2. 三层
1. **按引擎定位**：看游戏自己的文件。Unity 读 `*_Data/app.info` 里的公司名和产品名，算出 `LocalLow` 路径和注册表键；RPG Maker 看 `save` 目录和 `Save*.rvdata2`；Unreal、Ren'Py、KiriKiri、Wolf 等看对应目录。只提示实际存在内容的位置。
2. **玩一次对比**：记下开始时间，结束后找出之后改过的文件。只看文件名、时间、大小，不打开内容。范围：游戏目录、`AppData` 三个目录、`文档`、`Saved Games`。
3. **注册表存档**：Unity 的 PlayerPrefs。导出成稳定的 JSON，当普通存档文件备份、比对、上传。窗口分辨率这类每次都变的值不算，否则每次启动都像有新进度。

## 3. 什么时候记录
- 从 Atlas 启动存档位置还没定的游戏时，自动开始记录，游戏结束后自动查找。结束判断见[游玩记录报告](PLAY_TRACKING_REPORT.md)，启动器拉起的游戏也能跟踪。
- 需要管理员权限运行的游戏跟不到，用户点“我玩完了，查找存档”。
- 也可以手动点“开始记录”，然后用任何方式打开游戏。
- 已设置位置或确认没有存档的游戏不记录。

记录期间其他程序写入的文件也可能混入，所以结果分成“很可能”和“多半不是存档”两档。依据：是否在游戏目录、路径是否含游戏名、名字和类型是否像存档。浏览器、聊天软件、系统目录、缓存、日志直接跳过。

## 4. 存档规则的扩展
- `inside` 最后一段可以写一个通配符，如 `Save*.rvdata2`，新存档位也能覆盖。拒绝 `*`、`*.*`、`*.exe` 这类。
- 新增 `registry`：只能是 `HKCU\Software\公司\游戏`。`Microsoft`、`Classes`、`Policies` 等系统区域和 HKLM 一律拒绝。恢复前同样先备份，只写快照里有的值，不删其他值。
- 云存档和本地备份都走同一套，注册表存档也能跨机恢复。

## 7. 已知限制
- 没玩过、没存过档的游戏，按引擎也可能找不到，玩一次对比也看不到。
- 游戏要在记录期间真的写过存档才看得到；只开关一次通常没用。
- 记录期间其他程序写的文件可能混入“多半不是存档”，极少数会进“很可能”，所以要人看一眼。
- 存到本机以外的（游戏厂商自己的云、其他盘的自定义位置）看不到。其他盘不在扫描范围。
- `AppData`、`文档` 以外的位置要手动填。
- 每次最多访问 60 万个条目，超出时界面会说明没查完。
- 没识别加密或混在配置里的存档，文件夹级规则可能带上配置文件。
- 恢复只写快照列出的文件和值，不清理多余的。
